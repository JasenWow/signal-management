# Scenario 2: Overlap detection with repeatCount

## Setup
Message ID: 41b8a546-700e-4997-add7-e120d64d892d (frameSize=4, bitLength=32)

## Step 1: Create Group A (repeatCount=4, range [0, 32))
curl -X POST http://localhost:3000/api/messages/41b8a546-700e-4997-add7-e120d64d892d/groups \
  -H "Content-Type: application/json" \
  -d '{"name":"A","startBit":0,"bitWidth":8,"repeatCount":4,"color":"#FF0000"}'
Response: 201 Created - Group A created with isRepeating=true, repeatCount=4

## Step 2: Create Group B (startBit=24, bitWidth=8, range [24, 32))
curl -X POST http://localhost:3000/api/messages/41b8a546-700e-4997-add7-e120d64d892d/groups \
  -H "Content-Type: application/json" \
  -d '{"name":"B","startBit":24,"bitWidth":8,"color":"#00FF00"}'
Response: 201 Created

## Result: FAIL
Groups A [0, 32) and B [24, 32) overlap in bits 24-31 but no conflict was detected.
This is a bug in overlap detection - it only checks the first repetition of candidate groups.

## Actual groups in message:
- A: startBit=0, bitWidth=8, repeatCount=4, isRepeating=true (range: [0, 32))
- B: startBit=24, bitWidth=8, repeatCount=null, isRepeating=false (range: [24, 32))

## Expected: 409 Conflict
## Actual: 201 Created (no conflict detected)
